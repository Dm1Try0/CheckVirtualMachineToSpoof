# CheckVirtualMachineToSpoof

PowerShell-скрипт для локальной проверки Windows на распространённые признаки виртуальной машины. Он собирает сведения об оборудовании, системных идентификаторах, реестре и установленных компонентах виртуализации, затем показывает результаты в консоли.

> Скрипт выполняет эвристическую проверку. Его результаты не являются доказательством того, что компьютер физический или виртуальный.

## Возможности

- Проверяет названия и идентификаторы оборудования, опубликованные Windows через CIM/WMI.
- Ищет известные строки и MAC-префиксы, связанные с VMware, VirtualBox, Hyper-V, QEMU/KVM, Xen и другими платформами.
- Читает выбранные значения реестра, в том числе ветви с данными BIOS, Windows Update и SCSI-устройств.
- Проверяет наличие ACPI-датчиков температуры, гостевых служб и процессов, а также файлов драйверов виртуальных машин.
- Выводит результаты по разделам и выделяет подозрительные совпадения цветом.

## Требования

- Windows с Windows PowerShell 5.1 или PowerShell 7.
- Права администратора рекомендуются: без них часть системных сведений и ветвей реестра может быть недоступна.
- Дополнительные модули и сетевое подключение не требуются.

## Запуск

1. Скачайте репозиторий: нажмите **Code → Download ZIP** на GitHub и распакуйте архив либо клонируйте репозиторий.
2. Откройте **PowerShell от имени администратора**.
3. Перейдите в папку со скриптом, например:

   ```powershell
   cd C:\путь\к\CheckVirtualMachineToSpoof
   ```

4. Запустите проверку:

   ```powershell
   .\checkHwid.ps1
   ```

Если Windows блокирует запуск локального скрипта из-за политики выполнения, разрешите запуск только для текущего окна PowerShell и повторите команду:

```powershell
Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass
.\checkHwid.ps1
```

Изменение с областью `Process` действует только до закрытия этого окна. Не запускайте скачанный скрипт, если не доверяете его исходному коду: перед использованием просмотрите `checkHwid.ps1`.

## Что именно проверяется

### 1. Система и имя компьютера

Скрипт получает имя компьютера и пользователя, производителя и модель системы, UUID SMBIOS и серийный номер Windows. Также он отдельно отмечает имена компьютеров стандартного вида `DESKTOP-...`, `WIN-...` или `LAPTOP-...`.

### 2. Материнская плата и BIOS

Проверяются производитель и версия BIOS, его серийный номер, производитель и модель материнской платы и её серийный номер.

### 3. Процессор и гипервизор

Для каждого процессора выводятся его название и Processor ID. Дополнительно проверяется свойство `HypervisorPresent`, сообщающее, обнаружена ли Windows работающая среда гипервизора.

### 4. Видеоадаптеры и мониторы

Для видеоадаптеров отображаются название, PNP Device ID и видеопроцессор. Для мониторов — имя и PNP Device ID.

### 5. Диски и оптические приводы

Для дисков выводятся модель, серийный номер и PNP Device ID. Если обнаружены CD/DVD-приводы, отображаются их имя и PNP ID.

### 6. Оперативная память

Для каждого модуля памяти показываются производитель, номер детали (PartNumber) и серийный номер.

### 7. Сетевые адаптеры

Проверяются адаптеры, для которых Windows сообщает активное IP-подключение. Скрипт выводит описание и MAC-адрес адаптера и сравнивает начало MAC-адреса со списком распространённых префиксов виртуальных сетевых адаптеров.

### 8. Выбранные записи реестра и SCSI

Проверяются значения:

| Раздел | Значения |
| --- | --- |
| `HKLM\SOFTWARE\Microsoft\Cryptography` | `MachineGuid` |
| `HKLM\SYSTEM\CurrentControlSet\Control\IDConfigDB\Hardware Profiles\0001` | `HwProfileGuid` |
| `HKLM\SOFTWARE\Microsoft\Windows\CurrentVersion\WindowsUpdate` | `SusClientId` |
| `HKLM\HARDWARE\Description\System` | `SystemBIOSVersion`, `VideoBIOSVersion` |
| `HKLM\HARDWARE\Description\System\BIOS` | `BIOSVendor`, `SystemManufacturer`, `SystemProductName` |

Также скрипт рекурсивно обходит ветвь `HKLM\HARDWARE\DEVICEMAP\Scsi` и, если доступны, показывает значения `Identifier` и `SerialNumber`.

### 9. Записи ACPI

В ветвях реестра для таблиц `DSDT`, `FADT`, `RSDT` и `SSDT` просматриваются имена подразделов. Это диагностический признак, а не полная расшифровка содержимого ACPI-таблиц.

### 10. Косвенные признаки

- Проверяется наличие ACPI-термальных зон через WMI.
- В списке служб ищутся имена и отображаемые названия, связанные с VMware, VirtualBox, QEMU, VirtIO и некоторыми гостевыми драйверами.
- Среди запущенных процессов ищутся известные процессы гостевых утилит, например `vmtoolsd`, `vboxservice` и `qemu-ga`.
- В `%SystemRoot%\System32\drivers` проверяется наличие заранее перечисленных файлов драйверов VMware, VirtualBox и VirtIO.

## Как читать результат

- `[!]` — значение пустое либо совпало с одной из строковых сигнатур; для MAC-адресов и отдельных проверок есть специальные правила.
- `[+]` — проверяемое значение не совпало с известными строками из списка скрипта либо проверяемый компонент найден/не найден согласно конкретному сообщению.
- `[*]` — дополнительная заметка, например о стандартном шаблоне имени компьютера.

Для обычных текстовых полей используется список ключевых слов в начале скрипта: например, `VMware`, `VBOX`, `Virtual`, `QEMU`, `KVM`, `Xen`, `Hyper-V`, `Bochs`, `Parallels`, `VirtIO`, а также некоторые типовые или незаполненные значения вроде `To be filled` и `System Product Name`. Сравнение нечувствительно к регистру. MAC-адреса отдельно проверяются по заданным в скрипте префиксам.

Пустое значение в текстовой проверке помечается как `[!]`, поэтому такой результат может означать, что Windows или оборудование не предоставили данные, а не то, что найден виртуальный компонент. В то же время отсутствие совпадений не гарантирует физическую систему: сигнатуры могут быть изменены, скрыты или не входить в используемый скриптом список. Возможны и ложные срабатывания на физическом компьютере.

## Конфиденциальность

Отчёт может содержать имя пользователя и компьютера, UUID, серийные номера оборудования, идентификаторы устройств, системные GUID и MAC-адреса. Скрипт печатает их в консоль. Перед публикацией вывода, скриншота или лога удалите либо замаскируйте эти данные.

## Ограничения

- Проверяются только перечисленные в скрипте источники и сигнатуры.
- Результат зависит от версии Windows, драйверов, доступности CIM/WMI-данных и прав пользователя.
- Некоторые поля могут отсутствовать на физической системе; некоторые виртуальные машины могут не показывать очевидных сигнатур.
- Проверка не оценивает безопасность компьютера и не заменяет специализированную диагностику.
